## 数据和调用契约

- schema 升为 **v4**。旧 id、已有历史正文/旧哈希、边和 legacy 反馈计数保留；当前内容哈希、FTS 和 mentions 重建。新增来源、片段进度和事件去重账本。迁移整体处于事务中，时间/结构不合法时回滚并报错；开库失败会关闭连接。
- 旧数据的作用域先取规范化 cwd，否则取项目标签，最后为 global。显式 global 不因修改分类目录而改变。当前 scope 表示会话工作目录，不自动猜测 Git 根目录；无 cwd 的项目标签卡需通过全库范围检索发现。
- `writeFact` 返回 `{result,id,version}`；`upsertFact` 保留状态字符串兼容层。正文不截断，超过 1,000,000 字符明确拒绝。固定来源的 session/compaction 卡可同源修订。
- HTTP 新增返回真实 id/version，详情返回 scope/sources。阅读和引用分别记 open/cite；adopt/reject 仅通过明确反馈入口记账。无 sessionId 的面板/CLI 事件不能保证按会话去重。
- Markdown `base` 覆盖内容、元数据、版本与更新时间。旧格式同内容跳过，有修改且缺基线时报冲突；显式 `force` 可覆盖。重导出前应另存人工编辑。已有卡的 scope/cwd/source 元数据由库保留；正文、路径、标签、类型、状态和 confidence 可导入。每张卡失败会报告 `failed`，同批成功文件可提交。
- 提炼只对逐字引用、提供范围和版本做机械校验；这些校验不能证明模型结论在语义上一定正确。手动 `kb_add from` 只建立引用，不自动声明整个原料已处理。
- 旧悬空边保留以便核验，新建/修改端点不能指向不存在的卡。旧非法分类会在镜像导出时明确报错；不自动改名、删卡或合并。已被旧实现覆盖且无历史的正文无法凭当前库恢复。
