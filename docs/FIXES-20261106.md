## 迁移和数据契约

- schema **v5** 在开库事务中执行。保留旧卡 id、正文、历史、边和反馈数据；新增 `source_binding`，`fact_source` 增加源版本/hash，并允许同来源的不同版本记录。
- 旧来源无法确认支持哪个版本，迁移标记 `source_version=0`、空 hash，不把它冒充当前版本证据。独占会话来源建立未知基线绑定：首个相同内容吸收可确认基线，首次遇到不同内容则返回 `source-baseline-missing` 冲突，不覆盖旧卡。
- v4 曾合并多份来源的卡保留原身份和未知来源记录；后续吸收为独立来源新建卡，不自动删除旧卡、改写旧边或猜测历史归属。因而可能暂时出现保守保留的旧卡与新原料并存。
- 新来源基线包含 title/body/paths/tags/kind/confidence/ts。人工分叉且源也修改同一字段时，整张来源修订返回冲突；未变化字段保留人工值。状态始终由人工或遗忘流程管理。
- 引用证据查询按版本和哈希精确匹配历史快照。旧边没有结构化证据时保留原 note；不存在匹配快照时返回 null 并明确提示，不能伪造原文。
- 镜像 import 成功后会更新文件 frontmatter。SQLite 与文件系统无法形成同一个事务：数据库先提交，文件随后核对并确认；确认失败在 `failed` 中明确写明 `Database committed`。发生冲突时应保留文件并核验，不自动 force。未编辑的正文往返及只改元数据不会改变库内原始换行和空白；真正修改正文时仍按镜像的 LF/行尾规范写入。
- 旧 v4/v3 写入器不得与 v5 共用库；回滚需恢复匹配的代码与迁移前备份。本轮迁移验证只在测试库上执行。
