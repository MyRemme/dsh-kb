## P1：发布前优先修复

### A01 — 同标题全局合并会串项目，且覆盖没有历史

位置：[store.js:371](D:/Code/dsh-kb/lib/store.js:371)、[store.js:374](D:/Code/dsh-kb/lib/store.js:374)。

`hash=? OR title=?` 没有来源或项目边界。项目 A、B 都写“部署方式”，B 正文比 A 长 80 字以上时直接更新 A。复现结果只有一张卡：正文是 B，`path=project/alpha`、`source_ref=source-a`，版本仍为 1，历史 0 条。`hash` 与实际正文不符，FTS 路径却变成 `project/beta`。短正文的不同结论则可能被当作重复忽略。

**影响：** 内容、归属、来源和索引互相矛盾；旧正文没有进入版本历史。这个缺陷直接影响后续所有检索、提炼和追溯。

**修复与验收：** 同标题只能产生相似候选，不能直接决定身份或覆盖。引入稳定身份和明确作用域，修订必须经过事务化版本入口；正文、精确哈希、历史、来源、FTS、mentions 一起更新。跨项目同标题保留两张卡；同一卡显式修订保留 id，新增一版历史，各投影一致。

### A02 — 模糊指纹决定版本变化，语义修改静默丢失

位置：[store.js:328](D:/Code/dsh-kb/lib/store.js:328)、[store.js:649](D:/Code/dsh-kb/lib/store.js:649)。

`factHash` 去标点、空白和大小写，只保留归一化后标题前 200 字、正文前 2000 字。`updateFact` 用这个值判断正文是否变化。以下三种修改均实测返回 `unchanged`，数据库仍保存旧正文：

- `if (count > 0) allow();` 改成 `if (count < 0) allow();`。
- `API_KEY` 改成 `api_key`。
- 正文 2100 个字符之后，“禁止生产操作”改成“允许生产操作”。

**修复与验收：** 完整保存内容的精确比较/哈希用于修订检测；模糊指纹只用于相似候选召回。明确允许的规范化规则，并覆盖运算符、大小写、缩进和长正文尾部修改。新增内容哈希时保留既有卡 id，不要由新哈希重算旧 id。

### A03 — Markdown 镜像可写出指定目录

位置：[markdown.js:85](D:/Code/dsh-kb/lib/markdown.js:85)、[markdown.js:347](D:/Code/dsh-kb/lib/markdown.js:347)、[markdown.js:440](D:/Code/dsh-kb/lib/markdown.js:440)。

卡路径 `../../escaped` 保留了 `..` 路径段，`path.join` 解析后落到镜像根外。实测 `written=1`，目标相对镜像根为 `../../escaped/escape-proof--dd5e1842.md`。探针预先检查最终路径，整个复现仍在自建临时沙箱内。

**影响：** 一张带异常分类路径的卡就能让导出越出用户指定目录。HTTP 的 `safeDir` 只约束镜像根，不能约束每张卡派生的目标路径。已证实目录逃逸，未声称验证了任意文件名覆盖或远程利用。

**修复与验收：** 写入口拒绝非法路径段，导出器在所有 write/move/trash 操作前独立验证最终路径属于镜像根。补 Windows junction/symlink 场景；对既有不合法路径提供诊断或显式映射，不能继续原样导出。非法卡应明确报错，根外零写入。

### A04 — 图扩展绕过检索条件，并丢失关系语义

位置：[search.js:236](D:/Code/dsh-kb/lib/search.js:236)。

基础召回应用 `path/kinds/since/session/entity/status`，图扩展只检查目标 `active`，且所有关系都扩展。实测查询限定 `project/alpha + fix + 最近一天 + sess-alpha + 指定文件`，仍返回 300 天前的 `project/beta/episode`；两卡关系为 `contradicts`，返回只标 `why=graph`。另一个 `status=doubtful` 查询混入 active 邻居。

**修复与验收：** 所有召回通道共用过滤谓词。先确定上下文关系白名单；`contradicts/supersedes` 作为带方向和语义的独立证据展示，不能无差别拼成支持材料。各筛选条件分别测试，再测组合条件；图扩展不能放宽调用者明确指定的范围。

### A05 — 提炼一条结论就把整批原料标成已处理

位置：[distill.js:181](D:/Code/dsh-kb/lib/distill.js:181)、[distill.js:199](D:/Code/dsh-kb/lib/distill.js:199)、[distill.js:57](D:/Code/dsh-kb/lib/distill.js:57)。

输入两份互不相关的原料 A/B，假模型只输出 A 的 fix。实际仍建了两条来源边，B 也被当作已提炼；下一轮原料队列为空。图边同时承担“支持证据”和“整个原料处理完毕”两种不同含义。

**修复与验收：** 每条结论返回可校验的来源 id 和证据片段，只允许引用本批提供的材料。处理进度使用独立账本，至少关联源 id、源版本、处理范围、模型与提示版本。只处理 A 时 B 仍可入队；单条来源边不代表整张长原料已经完整处理，更新原料版本后可重新处理。

### A06 — 去重后重新算 id，产生不存在的结论与悬空边

位置：[distill.js:179](D:/Code/dsh-kb/lib/distill.js:179)。相关调用：[index.js:322](D:/Code/dsh-kb/lib/index.js:322)。

同标题的提炼结果被 `upsertFact` 判为 `dup`，保留已有卡 id；`saveDistilled` 却依据新正文计算另一个 id。实测返回的 id 不在 `fact` 表，仍写出一条以它为源的 `derived_from` 边，输入原料也因此被排除。`kb_add from=...` 有存在性判断，所以同类情况表现为静默缺失来源边。

**修复与验收：** 写入口返回实际 `{result,id,version}`，所有调用者使用该返回值。事实写入、版本历史和关系写入使用同一事务；建边检查两端存在性。`added/updated/dup` 三条路径都必须返回库中实际存在的 id，悬空边计数为零。

### A07 — 自动吸收违反“只降级、不淘汰”的契约

位置：[reap.js:119](D:/Code/dsh-kb/lib/reap.js:119)、[routes.js:439](D:/Code/dsh-kb/lib/routes.js:439)。

`/ingest` 显式传入 `purgeThreshold:0`，意图只变成 doubtful。`planReap` 用 `>0` 判合法，将 0 替换成默认 0.04。经正式 `/ingest` 处理器复现，一年前的 episode 变为 `superseded`，返回 `demoted=0, superseded=1`。这是错误标记失效，不是物理删除。

**修复与验收：** 参数解析区分“未提供”和合法的 0，校验有限数值及阈值范围；HTTP 参数层同样保留 0。完整吸收流程对老卡只能产生约定的 doubtful，`superseded=0`；显式淘汰操作另外验证。

## 两项需要调整产品语义的设计风险

**A18 — 使用反馈不能直接解释为“实测有用度”。** [index.js:391](D:/Code/dsh-kb/lib/index.js:391) 把 `kb_get` 直接记成 adopt。实测只读三次全文，就得到 `adopt_count=3`。另外 [usage.js:107](D:/Code/dsh-kb/lib/usage.js:107) 把曝光放进质量分母：三次否决为 -1，加上 1000 次曝光变为约 -0.00449；同样三次否决的卡，保留分由 0.128 升至约 0.63770。

建议分开 `shown/opened/cited/explicit_useful/explicit_wrong`。打开只表明阅读；质量主要依据明确反馈，曝光用于检索统计。按会话去重重试事件，明确错误反馈有待核验/失效通路，不能被曝光冲淡。近期确认有效可以影响保留策略；历史事件不能简单重新解释为用户已经确认采纳。

**A19 — 开场注入缺少作用域与内容信任边界。** [index.js:742](D:/Code/dsh-kb/lib/index.js:742) 选择全库最新 active 卡，忽略会话上下文；[index.js:745](D:/Code/dsh-kb/lib/index.js:745) 原样拼接标题。项目 B 的开场提示实测含项目 A 的标题，标题换行也能进入提示段。已确认数据进入提示文本，**没有测试或声称模型成功执行了恶意指令**。

本地全局记忆本身可以是产品选择，但应显式区分 global/project，并让用户控制跨项目检索。注入按当前作用域和相关性选卡，采用有长度限制、转义、带来源/版本的结构化数据块；固定规则声明记忆内容是待核验资料，不能把其中的指令升级为系统规则。提示边界不能只靠去掉一个换行符保证。
